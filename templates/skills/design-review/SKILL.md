# SKILL: design-review — 見た目の確認と修正のループ

見た目に関わる実装(HTML / CSS / コンポーネント)をしたら、**完了報告の前にこのスキルを実行する**。
AI はコードを書いた時点では自分の出力を「見て」いない。見ずに「できました」と言わないための仕組み。

## トリガー

- 見た目に関わる実装・修正をした時(毎回)
- ユーザーが「なんか違う」「ダサい」「見た目を確認して」と言った時

## 手順

### 1. 表示する

- ビルドツール構成 → dev サーバーを起動(起動コマンドは README 参照)
- 素の HTML → `index.html` をそのまま使う

### 2. スクリーンショットを撮る

- ブラウザ操作ツール(Playwright MCP / chrome-devtools MCP 等)が使えるなら、デスクトップ幅(1280px)とモバイル幅(390px)の 2 枚を撮る
- **使えない場合(手動フォールバック)**: ユーザーに 1 行で頼む
  > 確認したいので、ブラウザで開いてスクリーンショットを貼ってもらえますか?(できればスマホ幅も)

### 3. 基準と照合する

`@.claude/rules/design.md` を開き、スクリーンショットを見ながらチェックする。特に:

- [ ] 禁止項目を踏んでいないか(グラデ / 絵文字 / 均一カード羅列 / 多色 / 影・角丸の乱用)
- [ ] 余白: セクション間が詰まっていないか(迷ったら広く)
- [ ] タイポ: 行長・行間・階層は基準どおりか
- [ ] 色: ベース + アクセント 1 色に収まっているか、コントラストは読めるか
- [ ] 1 画面 1 主役になっているか
- [ ] モバイル幅で崩れ・はみ出しがないか
- [ ] 「このプロジェクトの審美眼」セクション(あれば)に反していないか

### 4. 直して、もう一度見る

- 修正はトークン(`@theme` / CSS カスタムプロパティ)から行うのが第一手
- 修正したら **必ず再スクリーンショット**で確認(最大 2 周。3 周目に入りそうなら、論点をユーザーに見せて判断を仰ぐ)

### 5. 報告する

完了報告に「design-review 済み(確認した幅: …)」と 1 行入れる。未実施のまま完了報告しない。
