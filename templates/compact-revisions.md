# リビジョン管理

`.project-memory/revisions/` にスナップショットを保存・整理する手順。

## いつ保存するか

### AI から先にアナウンスして保存する

以下の場面では、AI が**先にユーザーに伝えてから**スナップショットを保存します。

- ファイル全体を書き換える前
- ディレクトリ構造を変更する前
- 設定ファイル(`.claude/settings.json`、`package.json` 等)を変える前
- 一区切りの作業が完了した時
- 作業を中断する時(「今日はここまで」「続きは別の AI で」「Claude Code / Codex に切り替える」等)

→ 例: 「ここで一区切りなので、リビジョン保存しますね」と一言伝えてから保存。

### ユーザーの明示要求で保存

- 「リビジョンお願い」「セーブして」「ここまで記録して」「リビジョン取って」等

### 保存したあと(リビジョン保存と1セットで、続けて走る)

スナップショットを保存したら、**別々に頼まれなくても続けて**次を更新する(すべて同じ「セーブして」の一連の動作。これらは同時に走る):

- **ダッシュボード(毎回必ず)**: `dashboard.html` の `<script id="dashboard-data">` JSON の **`activity`(最近の動き)に 1 行追記**し、`updated` を今日の日付にする(HTML には触れない。全体の見直しはしない)。提案・できることに影響する変化があった時だけ、そこも追従する。更新したらチャットで一言添える(例: 「ダッシュボードにも記録しました。『ダッシュボード見せて』でいつでも開けます」)。マイルストーン完成の保存なら、OS に合わせて `open` / `start` でそのまま開いて見せる。
- **レシピドラフト**(`recipe/draft.md` が在る = レシピ追跡 ON の時だけ): その保存に含まれる **決定 / Phase 進行 / 固有値の置き場(プレースホルダ)** を `recipe/draft.md` の該当セクションに **1〜数行追記**する(append-only、整形しない)。**実値(ドメイン/実パス/氏名/メール/APIキー/デプロイ先)は書かない**(プレースホルダ名と「買い手に聞く」だけ。レシピは共有される前提=配る側の事故防止)。**技術地雷(踏んで直したもの)は draft に書かない** — 一次記録は該当 SKILL.md(無ければ CLAUDE.md)末尾の「ハマりどころ」1 箇所。この保存で解決した地雷がそこに未記録なら、draft ではなくハマりどころへ追記する。ファイルが無ければ何もしない(通常プロジェクト)。完成時にビルダーが結晶化して `recipe/{name}.md` にする(「ライブ捕捉 → 結晶化」方式。地雷=§6 はハマりどころから拾われる)。

→ レシピ追跡 ON のプロジェクトでは **リビジョン保存 / ダッシュボード / レシピドラフト の 3 つが 1 セット**で走る。どれか 1 つだけ更新して他を忘れない(大再設計の時は CLAUDE.md「アーキの肝」・design.md「審美眼」の散文も併せて見直す=散文の不変条件は grep では守れないため)。

### 保存しない

- 軽微な編集(typo、1〜2 行の調整)
- 自動生成物の更新

## ファイル名の規則

```
.project-memory/revisions/{YYYY-MM-DD-HHMM}_{きっかけ}.md
```

例:
- `2026-05-15-1430_before-CLAUDE.md-rewrite.md`
- `2026-05-15-1530_user-checkpoint.md`
- `2026-05-15-1700_milestone-completed.md`

## スナップショットに必ず書くこと

保存ファイルには次の型を使う。**中断時は「未完了タスク」「次にやること」を必須**とし、完了時に残りが無ければ「なし」と明記する。次の Claude Code / Codex がこのファイルだけで再開できる具体性にする。

```markdown
# {きっかけ}

- **保存理由**: なぜ今保存するか
- **完了したこと**: ここまでに終わった作業
- **決定事項**: 決めたことと、その理由
- **未完了タスク**: やりかけ・未着手・確認待ち。無ければ「なし」
- **次にやること**: 再開後の最初の一手。完了時に続きが無ければ「なし」
- **再開・検証コマンド**: 次の AI が必要とする時だけ記載。無ければ「なし」
- **検証結果**: 実行済みのテストと結果。未検証ならその理由
```

API キー、トークン、パスワード、生のコマンド出力などの秘密情報は保存しない。実行コマンドに秘密値が必要な場合は、値ではなく環境変数名やプレースホルダを書く。

変更前の退避が目的の保存(ファイル全書き換え前・設定変更前)では、上の型の下に自由形式の節(`## 変更前の内容` 等)を足して、書き換え前の内容の該当部分をそのまま貼る。型だけで済ませると復元材料が残らない。

## 整理のタイミング

リビジョンが **20 個を超えたら**、ユーザーに提案:

> リビジョンが 20 個を超えました。古いものを要約してアーカイブしますか?

OK が出たら以下を実行:

1. 古い順に読む
2. 月単位でまとめて要約
3. `.project-memory/revisions/archive/{YYYY-MM}-summary.md` に保存
4. 元のスナップショットを削除

## `ai-behavior.md` でのカスタマイズ

`ai-behavior.md` に「リビジョン管理」の項目があれば、そちらの設定(保存粒度・保持件数・整理頻度)を優先する。


## フェーズ別管理(Pro 版)

このプロジェクトは Pro 版で生成されている。個別スナップショット(変更前メモ)に加えて、**節目・マイルストーン記録**は `phases/NN-{name}.md` にフェーズ別で追記する構造になっている。

```
.project-memory/revisions/
├── INDEX.md                           ← フェーズ一覧表
├── phases/
│   └── 01-initial-setup.md            ← 最初のフェーズファイル
└── {YYYY-MM-DD-HHMM}_{きっかけ}.md     ← 個別スナップショット(変更前メモ)
```

### 何をどこに書くかの判断

| 種別 | 保存先 | 例 |
|---|---|---|
| 変更前の状態を退避したい | `{YYYY-MM-DD-HHMM}_{きっかけ}.md` | CLAUDE.md 全書き換え前 / 設定ファイル変更前 |
| 一区切りの達成・方針決定を残したい | 現在のフェーズファイル末尾 | 「ステップ X 完成」「設計案 5 個から 1 個に絞った」 |
| 章替えが始まった | 新フェーズファイル + INDEX.md 更新 | 「初期セットアップ完了 → 本番運用フェーズ開始」 |

### 節目記録の書き方

現在のフェーズファイル(`phases/NN-*.md`)末尾に `## [YYYY-MM-DD] {見出し}` で追記。中身は:

- **発見**: 何に気づいたか / 何が完成したか
- **場所**: 関連ファイル
- **変更**: 何を変えたか
- **理由**: なぜそうしたか
- **未完了タスク**: 残っていること。無ければ「なし」
- **次にやること**: 再開後の最初の一手。無ければ「なし」

長く書きたい時はその下に自由形式の節を足す(`## なぜ保存したか` 等)。

### 新しいフェーズを開始するタイミング

以下のような大きな方向転換が起きたら、ユーザーに「新しいフェーズに分けますか?」と提案する:

- プロジェクトの目的・スコープが変わった
- 技術スタックの大きな入れ替え
- 「初期セットアップ → 本番運用 → 改善ループ」のような明確な章替え

OK が出たら:

1. `phases/NN+1-{kebab-name}.md` を作成(Phase 1 のひな型をベースに見出しを書き換える)
2. `INDEX.md` の「フェーズ一覧」表に行を追加(`# / フェーズ / 期間 / テーマ / ファイル`)
3. 新エントリは以降この新ファイルの末尾に追記

### アーカイブ対象の違い

- **個別スナップショットが 20 個超** → 月単位要約してアーカイブ(従来通り)
- **フェーズ別ファイル** → 長期保存。アーカイブしない

理由: 節目記録は後から「なぜこの設計にしたか」を読み返すための資産。要約で失われたら意味がない。
