# 自己改善ループ

エラーや想定外の挙動に遭遇した時、以下の順で動いてください。

## 1. 何が壊れたかを特定する

- エラーメッセージとトレースの全文を読む
- どのワークフロー / スクリプトで起きたか特定する
- ユーザーに見せる前に、まず自分で原因を理解する

## 2. ツールを修正する

- 該当するスクリプト(`.claude/skills/{name}/`)を修正
- **有料 API・課金が絡む再実行は必ず確認を取る**
- 軽微なものは自己修復してから報告

## 3. 修正が機能することを確認する

- 同じ操作で再発しないか確かめる
- 副作用が出ていないか周辺もチェック

## 4. 学びを記録する(着地点)

**記録先のルール**:

1. **該当する `.claude/skills/{name}/SKILL.md` の `## ハマりどころ` セクションに追記**(エラーが特定スキルの操作で発生した場合)
   - 例: `notion-sync` スキルでレート制限に当たった → `.claude/skills/notion-sync/SKILL.md` 末尾の `## ハマりどころ` に学びを追記
   - 枠が定義されているので、迷わずそこに書く(セクションごと探す必要はない)
2. **該当スキルが無いプロジェクト(skill 不在)** の場合は、**`CLAUDE.md` 末尾の `## ハマりどころ` セクション**に追記
   - ビルダーが生成時に CLAUDE.md にも同じ枠を置いている
3. **判断に迷う場合**(複数スキルに跨る等)は、ユーザーに「どこに記録すべきか」を 1 問だけ確認してから追記

**追記の型(3〜5 行で)**:

```markdown
### {現象を一行で}(YYYY-MM 検証)

- 現象: 何が起きたか
- 原因: なぜ起きたか
- 対処: どう直したか(なぜそれが効くか)
```

**役割境界(混ぜない)**:

- **技術ハマり(ここ)** → SKILL.md の `## ハマりどころ` / skill 不在なら CLAUDE.md の `## ハマりどころ`
  - そのうち「**このスタック / ツールを使う人なら誰でも踏む**」一般的なものは、ビルダー本体の `knowledge/{stack}.md` への**昇格候補**。このプロジェクト内では従来どおり `## ハマりどころ` に残しつつ、ビルダーを触る時に「これ knowledge にして」と引き上げる(このプロジェクト固有の値・絶対パス・鍵は持ち込まない)
- **業界・ドメイン判断の地雷** → `domain-knowledge.md`(Pro 版のみ存在)
- **個人の事実 / 振る舞い指示** → aboutme.md / ai-behavior.md

ただし、**`SKILL.md` / `CLAUDE.md` の他のセクションを上書きする時は必ず確認を取る**。
これらは指示書であり、勝手に書き換えるものではない(ハマりどころ枠への追記は例外)。

## 5. リビジョンを残す

大きな修正をした時は `.claude/commands/compact-revisions.md` の手順で
スナップショットを `.project-memory/revisions/` に保存。

---

**原則**: 失敗はすべてシステムを強化する機会。
「ごめんなさい」より「次から壊れない仕組み」を作ること。
