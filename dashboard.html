使い方(最初の一歩)

あなたが Claude Code または Codex で何かを作ろうと思ったら、このツールに話しかけてください。ヒアリング内容から、プロジェクト内容をしっかり書き込んだ CLAUDE.md、必要に応じた AGENTS.md、.claude/、.codex/ など必要なもの一式が自動で作られます。言い換えるなら、選択した AI が自律的に、安全で的確に働ける仕事場を作るツールです。

事故らないパスワードや API キーを初日にうっかり公開しない仕組みを最初から装備
リミットに達しにくいリミット(利用上限)に達しにくくする自動提案をします
使うほど賢くなる失敗や気づきが記録されて資産になる。同じ説明を毎回しなくていい
デザインの AI っぽさを除去「AI が作りがちな無難で安っぽいデザイン」を防ぐ
1
ZIP を解凍して、好きな場所に置く
ダウンロードした ZIP ファイルを解凍(ダブルクリック)し、出てきた kote2-builder フォルダを任意の場所(書類フォルダなど)に配置します。
2
ビルダーのパスをコピーする
VS Code のサイドバー(エクスプローラー)で kote2-builder フォルダを右クリックしてメニューを開き、「パスをコピー」を選択します。Codex でフォルダを直接開く場合は、この手順を飛ばしても構いません。
フォルダがサイドバーに見えていない時は、メニューの「ファイル」→「フォルダーを開く」でビルダーのフォルダを開いてから右クリックしてください。
3
Claude Code または Codex で開く
Claude Code: Mac は ⌘ + Shift + P / Windows は Ctrl + Shift + P でコマンドパレットを開き、Open in New Tab を選びます。
Codex: kote2-builder をワークスペースとして開き、信頼できる配布元の場合だけ project と Hook を信頼します。
4
「ビルダー起動」と話しかける
Claude Code では入力欄の 1 行目にコピーしたパスを貼り付け、改行して「ビルダー起動」と入力します。Codex でフォルダを開いた場合は、そのまま「ビルダー起動」と入力します。
入力例/Users/あなたの名前/Documents/kote2-builder ビルダー起動
5
作りたいものを答える
ビルダーが挨拶して「何を作りたいか」を聞いてきたら成功です。作りたいものをひとこと入力してください。質問攻めにはしません——ビルダーが設計書を見せてくるので、OK を出せば初期プロジェクト一式がビルダーのフォルダ直下の output/ に生成されます。
あとからで OK:あなたの情報を教える(3 つのファイル)

ビルダーには、あなたのことを覚えてもらうファイルが 3 つ入っています。全部空欄のままでも動くので、まずは起動して触ってみて OK。余裕が出たら埋めると、AI の提案が的確になっていきます。

aboutme.md — あなたの基本情報
名前・業種・使っているツール・目標など。書ける範囲で OK です。
ai-behavior.md — AI への要望
口調・避けてほしいことなど。こちらも空欄 OK です。
design-knowledge.md — デザインの希望(Web サイトを作る人向け)
色・書体・余白の流儀・NG・参考サイトなど、あなたの審美眼を書くファイル。先に書いておけば、生成される全プロジェクトに引き継がれます。空欄でも標準のデザイン基準で動きます。

どれもビルダーのフォルダ直下にあります。VS Code で開いて直接書いても、Claude に「aboutme を一緒に埋めて」と頼んでも構いません。

レシピを取り込んで「同じものを再現」する

配布されているレシピ(作り方の設計書)を取り込むと、紹介されていた成果物をあなたの手元で再現できます。

① 配布されたレシピファイル(〇〇.md)を recipes/ フォルダ(無ければ作る。サブフォルダで整理しても OK)に置く
② ビルダーを起動して 「このレシピで作って」 と言う

あとは AI がレシピの「建てる順番」「つまずき所の直し方」に沿って output/ に一式を組み立てます。

Free 版は取り込んで再現するところまで。自分のビルドをレシピ化して共有する側と検証済みレシピの同梱カタログは Pro 版の機能です。

新しいバージョンへの引っ越し(移行)

ビルダーが新しいバージョンになったら、前のフォルダで貯めた設定・レシピ・記録と、あなたが作った作品(output)を、新しいビルダーに引き継げます。古いフォルダはそのまま残るので安心です。

1
新しいビルダーを開いて、引っ越しを頼む
新しいバージョンのフォルダを Claude Code または Codex で開き、古いビルダーフォルダのパスと「旧ビルダーの内容をこの本体に移行して」を一緒に送信します。
入力例/Users/あなたの名前/Documents/前のビルダーフォルダ 旧ビルダーの内容をこの本体に移行して
2
「何を移すか」を確認して OK する
AI が移行設計書(=何を引き継ぐかの一覧)を見せます。中身を確認して OK と言えば、設定・レシピ・記録は AI が引き継ぎます。いきなりコピーはしないので安心です。
3
作品(output)は自分の手でコピー
あなたの作品が入った output フォルダは大切なので、AI は勝手に動かしません。古いフォルダの中の output フォルダを、新しいビルダーの中にドラッグしてコピーしてください(Mac は Finder、Windows はエクスプローラー)。コマンドのほうが良ければ、AI に言えば(お使いの Mac / Windows に合わせて)出してくれます。

あなたの個人情報(名前など)は各プロジェクトの中に入っているので、output を運べば一緒に付いてきます。取りこぼしはありません。ビルダー直下の aboutme.md が空に見えても心配いりません。

Pro 版でできること

レシピ(共有できる「作り方の設計書」)
Web やアプリを作ると、AI が作りながら「決めたこと・作った順番・つまずいた所の直し方」を自動で recipe/draft.md に記録していきます。一区切りしたら「このプロジェクトのレシピを作って」と頼むと、共有用のレシピができます。ドメイン名・パス・メール・API キーなどの実値は最初から書かず、完成時に機械チェックもするので、安心して共有できます。
ドメイン知識ファイル(domain-knowledge.md)
あなたの業界知識(判断軸・地雷・用語)を AI に渡す専用ファイル。domain-samples/ に業種別のお手本が入っています。書き終わったら「ドメイン知識をチェックして」と頼むと、AI が読んで質問しながら精度を上げてくれます。
スキル提案ボード
AI があなたの作業を見ていて「これ、ボタン一発の定型作業にしませんか?」と提案してくれる仕組み。提案はプロジェクトのダッシュボードに表示され、「スキル化して」と返事をすればそのまま作ってくれます。
開発者モード(ビルダー本体のカスタマイズ)
ビルダーの振る舞いそのものを AI と一緒に編集できるモードです。切り替えはターミナルで cp CLAUDE.dev.md CLAUDE.md、通常モードに戻すのは cp CLAUDE.live.md CLAUDE.md。切り替えたら使用中の Claude Code または Codex を一度閉じて開き直してください。詳しくは README.md を参照。
