# /dashboard — プロジェクトダッシュボードの更新・表示

このプロジェクトの「情報ページ」(プロジェクト直下の `dashboard.html`)を最新化して、ブラウザで開いて見せるコマンドです。

> 言葉でも呼べます。「ダッシュボード見せて」「何ができるんだっけ」「最近の状況見せて」
> のように話しかけられた時も、この手順を実行してください。
>
> リビジョン(修正履歴)を保存した直後は、この手順の **4(最近の動き)だけ**を必ず更新してください
> (全体の見直しは不要)。詳しくは `/compact-revisions` の「保存したあと」を参照。

## 更新のしかた(重要)

`dashboard.html` の中の `<script id="dashboard-data">` にある **JSON だけ**を Edit で書き換える。
**HTML / CSS / JS には触れない**(デザイン崩れ防止。件数タイル・空状態は自動で追従する)。
スキーマは JSON ブロック直上のコメントに書いてある。文章はプレーンテキスト(HTML タグ・Markdown 記法を書かない)。

`dashboard.html` が無い・壊れている時だけ、雛型 `.claude/.tmp/dashboard.template.html` の
`{{DATA_JSON}}` を実データで置換してプロジェクト直下に書き出す(再生成)。

## 手順

1. **データ収集**:
   - `CLAUDE.md` の「できること」リスト
   - `.project-memory/revisions/`(直近 5 件程度)
   - `.project-memory/skill-ideas.md`(存在する場合のみ。無ければスキル提案は黙って省略)
   - `recipe/draft.md`(存在する場合のみ = レシピ追跡 ON の印。無ければレシピ関連は黙って省略)
   - `automations.md`(存在する場合のみ = 台帳方式の印。無ければ関連プロジェクトは黙って省略)
   - `README` 末尾の刻印(生成バージョン・日付)
2. **`proposals`(今のあなたへの提案)を組む(最大 5 件)**:
   - skill-ideas のアクティブ提案(あれば。ライフサイクルは skill-ideas.md 側のルールに従う)
   - `design-knowledge.md` が未記入なら記入のナッジ(Web 系のみ。一度断られたら再提案しない)
   - 生成バージョンがビルダーの現行より古いと分かっている場合はアップデートのすすめ(ビルダー側で「○○をアップデートして」)
   - その他、リビジョンから読み取れる「次の一手」(例: 「写真の差し替えが残っています」)
   - `recipe/draft.md` が在り、プロジェクトが一区切り(完成・大きな緑)に見えるなら「このプロジェクトのレシピ(共有用設計書)を作れます」の提案(一度断られたら再提案しない)
3. **`catalog`(できること)を CLAUDE.md と同期**(機能が増えていたら行を足す。
   形式は `{ "want": 困りごと, "say": 話しかけるセリフ }`)。`recipe/draft.md` が在る時だけ、レシピ行も足す:
   `{ "want": "このプロジェクトの作り方を共有用レシピにしたい", "say": "このプロジェクトのレシピを作って" }`
3.5. **`linked`(関連プロジェクト)を台帳と同期**(`automations.md` がある時だけ。登録 1 件 = カード 1 枚、
   形式は `{ "name", "desc": できること 1 行, "say": 呼び出しの一言, "freq": 目標・頻度, "place": 場所 }`。
   say / freq / place は台帳に書いてなければ省略。台帳が無い・空なら `linked` を書かない = 枠ごと非表示)
4. **`activity`(最近の動き)を更新**(リビジョンから新しい順に 1 行ずつ。`updated` も今日の日付に)
5. **ブラウザで開いて見せる**: OS に合わせて `open dashboard.html`(Mac)/ `start dashboard.html`(Windows)。
   ユーザーが「見せて」と言った時・このコマンドで呼ばれた時は必ず開く(更新だけで終わらせない)
6. **差分報告**: チャットで一言(「提案 1 件追加 / できること 1 行更新。ブラウザで開きました」。
   変化が無ければ「変化なし」と正直に言う)

## 原則

- 提案は必ずライフサイクルに落とす(実装済み / 却下 / 失効)。**読まれないカードの山にしない**
- `dashboard.html` を手編集の真実の源にしない(提案の真実の源は `skill-ideas.md`、できることの真実の源は `CLAUDE.md`、関連プロジェクトの真実の源は `automations.md`)
- 関係ない会話でダッシュボードの話を持ち出さない
- JSON が壊れると画面に復旧案内が出る。「ダッシュボード直して」と言われたら、雛型から再生成して JSON を組み直す
