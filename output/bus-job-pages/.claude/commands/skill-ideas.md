# /skill-ideas — リビジョンからスキル化候補を提案する

作業ログ(リビジョン)を読んで「何度も繰り返している作業」を見つけ、
スキル化の候補を提案ボードにまとめて見せるコマンドです。
**勝手にスキルは作りません。提案 → あなたの承認後に実装**します。

> 言葉でも呼べます。「スキルにできるもの教えて」「最近の繰り返しスキルにできる?」
> のように話しかけられた時も、`/skill-ideas` と同じこの手順を実行してください。

## 手順

1. **読む**: `.project-memory/revisions/` 配下のスナップショットと `phases/`(あれば)を全部読む。
2. **抽出**: 「同じ手順・同じ修正・同じ依頼」が **3 回以上**現れるパターンを探す。
3. **除外**: `.project-memory/skill-ideas.md` の「実装済み」「却下」にあるものは候補から外す。
4. **間引き**: アクティブ提案は**最大 5 件**。出現回数が多い=根拠の強いものを優先し、
   弱いカード・元パターンが出てこなくなったカードは「保留(失効)」に落とす。
5. **更新**: `.project-memory/skill-ideas.md`(真実の源)を書き換える。各カードは
   `### タイトル` の下に **根拠(どのリビジョンか)/ 想定スキル名 / 状態** を書く。
6. **レンダリング**: `/dashboard` の手順を呼び、アクティブ提案を `dashboard.html` の
   「今のあなたへの提案」セクションに反映する(専用ページ `skill-ideas.html` は作らない)。
7. **差分報告**: 書き換える前のボード状態と比べて、何が変わったかをチャットで一言報告する:
   - 例: 「新規 2 件 / 失効 1 件 / 実装済みへ移動 0 件。`dashboard.html` を開いて確認してください」
   - 新規が 0 件なら「新しい候補はありませんでした」と正直に言う(更新があったフリをしない)。
   - これが「ユーザーが更新に気づく」ための主要な合図。html は"じっくり見る用"、チャットは"差分の通知"。
8. **マーカー更新**: `.project-memory/runtime/markers/skill-ideas-seen` に現在のリビジョン件数を書き込む
   (次回のナッジ判定の基準)。

## あなた(ユーザー)の反応への対応

- **「これ実装して」「スキル化して」** → そのカードを元に `.claude/skills/<スキル名>/SKILL.md` を作る
  (必要なら `run.ts` / `run.py` も)。CLAUDE.md の「できること」リストに 1 行追記。
  カードを「実装済み」へ移して `skill-ideas.md` と `dashboard.html` を更新。
- **「これは要らない」** → カードを「却下」へ移す。
  **却下したパターンは再検出しても二度と提案しない**。

## やらないこと

- 勝手にスキルを作らない(必ず提案 → 承認後に実装)。
- 提案を無限に溜めない(5 件上限 + 却下/失効で間引く。ボードは常に「今おすすめの数件」だけ)。
- `dashboard.html` を真実の源として手編集しない(提案の真実の源は常に `skill-ideas.md`)。
