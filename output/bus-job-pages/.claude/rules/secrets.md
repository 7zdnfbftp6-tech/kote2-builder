# 秘密情報を扱う時のルール

**参照タイミング**: API キー / サービスアカウント JSON / `.env` 系のファイルや値を **実際に扱う作業に入る時** だけ読む。通常会話では読まない。

---

## 中身に触れない

秘密ファイル(`.env`, `*.json` の credentials, `.dev.vars` 等)の **中身を読まない / 出力しない / ログに残さない**。`cat .env` のような取得系コマンドも避ける。

## 「中身を読まない」と「ユーザーに丸投げ」は別物

中身に触れないからといって、シェルの引用符・改行・マルチライン JSON のような扱いにくい処理を **ユーザーの手打ちに任せない**。AI 側で次のような経路を設計して、自分の手で実行する:

- ファイルパスだけ受け取って、中身に触れないコマンドで処理(`cp`, `mv`, パイプ経由 redirect 等)
- helper スクリプトを書き、ユーザーには「これを実行してください」だけを渡す
- マルチライン JSON は `python -c 'import json,sys; json.dump(...)'` 等で確実にエスケープする
- `zsh` の `echo` で改行が消える罠を避け、`printf` や heredoc を使う

## 安全ライン(生成時に既に組み込み済み、確認用)

- `.env` / `.env.local` / `.dev.vars`(Workers 系)は `.gitignore` に入っている
- `.env.example` が雛形として用意されている
- README に「`.env` は危険ファイルではなく秘密情報を置くファイル。危険なのは外に出すこと」の説明がある
