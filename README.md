# kote2 Builder(Pro 版)

> 「作りたいものに集中できる」Claude Code / Codex プロジェクト自動構築ツール

Claude Code / Codex 用のプロジェクト初期化ビルダー(カスタマイズ可能版)。
作るのは「プロダクト」ではなく、選択した AI が自律的に、安全で的確に働ける**仕事場**です。

ビルダーの基本(4 つの約束 = 事故らない / リミットに達しにくい / 使うほど賢くなる / デザインの AI っぽさを除去、使い方、ダッシュボード、アップデート)は Free 版のガイドと共通です。本書は **Pro 版で増えるもの**に絞って説明します。

**Pro 版の特徴**: ビルダーの振る舞いそのもの(`builder.md`)を編集できます。

生成するプロジェクトは、**Claude CodeとCodexの両対応**または**Claude Codeのみ**から選べます。**ビルダー自体もClaude CodeとCodexのどちらからでも起動できます。** 最初の質問で生成物の対応先を選ぶだけです。番号が無い・迷った場合は、おすすめの両対応で進みます。Claude Codeのみで始めても、あとから「Codex対応にして」と頼んで非破壊で追加できます。Codex対応はFree／Pro共通で、Pro専用機能も同じプロジェクトファイルを正本として共有します。両対応の生成物では「**このプロジェクトの仕組みを画像化して**」と頼むと、Codexが実装や要件を確認し、内容の関係に合う図法を選び、1080pでの可読性と矢印の事実関係も検査した非エンジニア向けの図解を作ります。

## Free 版との違い

| | Free | Pro |
|---|---|---|
| `aboutme.md` / `ai-behavior.md` | 編集可 | 編集可 |
| **`builder.md`** | 編集非推奨 | **編集して振る舞いをカスタマイズ可能** |
| **開発者モード**(`CLAUDE.dev.md`) | なし | **同梱・切り替え可能** |
| **ドメイン知識ファイル**(`domain-knowledge.md`) | **なし** | **同梱**(業種別お手本 `domain-samples/` 付き) |
| **レシピ**(再現用の設計書) | 取り込み再生 + 無料サンプル 1 本 | **検証済みカタログ同梱 + 「作る側」**(下記) |
| **スキル提案ボード**(skill-ideas) | なし | **生成プロジェクトに同梱**(ダッシュボードに統合表示) |
| **フェーズ別リビジョン管理** | 基本のみ | **生成プロジェクトに INDEX + フェーズ構成を同梱** |
| `builder.md` 内の「拡張可能ポイント」案内 | なし | **同梱** |

> Pro 版は別途 Claude Code 講座(およびユーザーコミュニティでの活用事例共有)とセットで提供されます。製品単体の差分は上記ですが、運用ノウハウ・成長機会は講座/コミュニティ側にあります。

## レシピ — カタログを使う・自分のビルドをレシピにする(Pro 版の目玉)

**レシピ**は「成果物を丸ごと再現する設計書」です。完成形だけでなく、**建てる順番(Phase + 各段の検証)とつまずき所の直し方**まで持っているので、AI が一気に作って動かない、を避けられます。

- **検証済みカタログ同梱**: `recipes/official/`(カテゴリ別フォルダ)に、実際に建てて検証済み(verified)のレシピが最初から入っています。自分のレシピは `recipes/` 以下に好きなフォルダを作って置けます。「**レシピ一覧見せて**」で一覧、「**このレシピで作って**」で再現が始まります。
- **作る側(ライブ捕捉 → 結晶化)**: Web・アプリ系のプロジェクトを作ると、AI が「セーブして」のたびに設計判断や建てた順を自動で記録します(レシピ追跡)。完成したら「**このプロジェクトのレシピを作って**」で共有用レシピに仕上がります。
- **個人情報は構造的に入らない**: 実ドメイン・実パス・氏名・API キーなどの実値はレシピに書かれず、「買い手に聞く」プレースホルダに置き換わります。仕上げ時に機械チェック(シークレット走査)も通ります。安心して配れます。

## ドメイン知識ファイル(Pro 版の実験機能)

`domain-knowledge.md` は、あなたの業界・ドメイン知識を AI に渡すための専用ファイルです。
3 ファイル協定の一角として、aboutme.md / ai-behavior.md と役割を分けて使います。

| ファイル | 主語 | 役割 |
|---|---|---|
| `aboutme.md` | 私は〜 | 個人の事実(誰、何の仕事、目標) |
| `ai-behavior.md` | AI は〜 | AI への振る舞い指示 |
| **`domain-knowledge.md`** | **この業界では〜** | **業界・ドメイン知識(判断軸、地雷、用語等)** |

### 何を書くか

**自由形式**で OK です。カチッとしたフォーマットに沿わなくても構いません。
業務の進め方や大事なポイントを、自分の言葉で書いてください。

例えば:

- 業界特有の地雷(言ってはいけない表現、商習慣の禁忌)
- 判断の分かれ目(こうなったらこうする、というルール)
- 顧客タイプ別の対応の違い
- 業界用語(一般語と意味が違うもの)
- 信頼できる情報源

「全部書く」必要はありません。重要なものから書ける範囲で OK。

### 業種別のお手本(domain-samples/)

`domain-samples/` フォルダに業種別のお手本ファイルが入っています。一覧は `domain-samples/INDEX.md` にあります。自分の業種に近いものを開いて、書き方を真似てください:

- `domain-samples/domain-knowledge-seo.md` — SEO 担当者向け
- `domain-samples/domain-knowledge-designer.md` — デザイナー・Web 制作者向け

あなたの業種がお手本とマッチした場合は、ビルダー自身が設計書の段階で「このお手本を下敷きにしますか?」と提案します。
(今後、業界経験者の協力を得て業種別お手本を順次追加していきます)

### AI に読んでもらう

書き終わったら、Claude に **「ドメイン知識をチェックして」** と頼んでください。

AI が `domain-knowledge.md` を読み、不明な点・業務判断に活かしづらい箇所があれば「これってどういうこと?」と質問します。質問のやりとりを通じて、知識がさらに精度高く蓄積されていきます(AI は勝手にファイルを書き換えず、必ず許可を取ってから追記します)。

ファイルが空でも、AI は定型説明と書き出しの伴走を行います。

### なぜこれが効くのか

LLM は「個人事実 / AI への指示 / 業界知識」が同じファイルに混在すると役割判定がブレ、出力が不安定になります。**主語で分離する**(私は / AI は / この業界では)ことで、出力精度が一段上がります。

「ファイル 1 つ追加するだけ」ですが、自分専用の AI エージェントを作る上で最も効くピースの一つです。

## スキル提案ボード(Pro 版限定)

Pro 版で生成したプロジェクトには、**AI があなたの作業を見ていて「これ、スキル(ボタン一発の定型作業)にしませんか?」と提案してくれる仕組み**が入ります。

- 提案はプロジェクトの `dashboard.html`(「今のあなたへの提案」)に表示されます
- 提案は最大 5 件まで。一度断った提案はしつこく再提案しません
- 「スキル化して」と返事をすれば、AI がそのままスキルを作ります

使うほど定型作業がボタン化されていく——「使うほど賢くなる」の Pro 版の主役です。

## 2 つのモード(動作モード / 開発者モード)

Pro 版には 2 つのモードがあり、`CLAUDE.md` を切り替えることで使い分けます。

| モード | アクティブファイル | AI の振る舞い |
|---|---|---|
| **動作モード**(デフォルト) | `CLAUDE.md` = `CLAUDE.live.md` の中身 | ビルダーとしてプロジェクト生成を担当 |
| **開発者モード** | `CLAUDE.md` = `CLAUDE.dev.md` の中身 | ビルダー本体のカスタマイズを伴走 |

### 切り替え方

```bash
# 開発者モードに切り替え(builder.md などを AI と一緒に編集)
cp CLAUDE.dev.md CLAUDE.md

# 動作モードに戻す(通常のビルダーとして使う)
cp CLAUDE.live.md CLAUDE.md
```

切り替えたら、使用中の Claude Code または Codex を一度閉じて開き直してください。Codexでも同じ`CLAUDE.md`をモードの正本として読むため、追加の切り替え操作は不要です。

### 想定ユースケース

- **チームでカスタマイズしながら使う**: 開発者モードで自社用に builder.md を仕上げて、動作モードで全員が利用
- **クライアント納品前にチューニング**: 開発者モードでクライアントの業界に合わせて調整 → 動作モードで納品
- **業界知識の蓄積**: `domain-knowledge.md` に業界判断軸・地雷・用語を書き込んで AI を専門化(本書「ドメイン知識ファイル」セクション参照)

## 基本的な使い方

Free 版と同じです。

1. 「ビルダーを起動」または「はじめて」と話しかける
2. あとからで OK: `aboutme.md` / `ai-behavior.md` を埋める(空欄でも動きます)

**Codexで初めて開く時**は、この配布元を信頼できる場合だけprojectを信頼し、`/hooks`でビルダー本体の`SessionStart` 1件（90日ごとの棚卸し案内）を確認して信頼してください。

画面の開き方から順を追った手順は、使い方マニュアルを兼ねた同梱の**玄関ページ(`dashboard.html`)**を参照してください(ダブルクリックでブラウザが開き、レシピ在庫や作ったプロジェクトも一望できます)。

## カスタマイズ例

### 例 1: 自社の流儀を埋め込む

デザインの流儀(色・書体・NG)は `design-knowledge.md` に書きます(Web 系の生成時にデザイントークンまで焼き込まれます):

```markdown
■ブランドカラー・色の好み
メイン: #0F4C5C / アクセント: #E36414。背景に色を敷かない。

■NG(絶対やらないでほしいこと)
絵文字を UI に使わない。グラデーション禁止。
```

構成・スタックの標準(使うフレームワーク、必ず同梱するフォルダ等)は `usecase/web.md` の該当箇所に追記します(`builder.md` 本体は薄く保つのが v3 の流儀です)。

### 例 2: クライアント別の設定

複数のプロファイルを作っておいて、案件ごとに差し替え:

```
aboutme.client-a.md
aboutme.client-b.md
ai-behavior.client-a.md
ai-behavior.client-b.md
```

ビルダー起動前に `aboutme.md` / `ai-behavior.md` を該当クライアント版で上書きしてから起動します。

### 例 3: 業界特化のスキルを標準搭載

`templates/skills/` に業界特有のスキル(例: WordPress 案件初期化スキル、Shopify 初期化スキル等)を置き、`usecase/{name}.md` に「この用途の時に同梱する」と配置条件を 1 行書くと、生成時に自動で同梱されます(標準搭載の design-review / page-factory と同じ仕組みです)。

### 例 4: 口調プリセットを増やす

`.claude/output-styles/` に追加プリセットを置けます:

- `output-styles/default.md` — 標準
- `output-styles/strict.md` — 厳格モード(エンジニア向け)
- `output-styles/coaching.md` — コーチング向け(柔らかい口調)

ユーザーは `/output-style {name}` で切り替えできます。

## カスタマイズの注意

- `builder.md` を編集する前に必ずバックアップを取ってください
- 「動作原則(変えない)」セクションは基本的に編集しないことを推奨します(振る舞いが大きく崩れる可能性があります)
- カスタマイズ箇所には `<!-- CUSTOM: ... -->` 形式のコメントを残しておくと、後で見返しやすくなります
- 編集後は必ず実走テストで動作確認してください

## 自己修復 hooks(macOS / Linux 向け)

生成プロジェクトに `.claude/hooks/` 経由の**deterministic な自己修復メカニズム**が組み込まれます。Codex両対応時は同じ安全化済みイベントをCodex側のHookも読みます。

- **動作**: Bash の `exit != 0` を、秘密除去済みの1失敗=1 JSONとして `.project-memory/runtime/errors/` に保存 → Claude CodeまたはCodexの応答終了時に未解決エラーがあれば一度だけself-healフローを促す
- **共有と分離**: 引き継ぐ作業記憶だけを`.project-memory/`で共有し、`.claude/.tmp/`と`.codex/.tmp/`は各エージェント固有の一時状態として混ぜない
- **対応 OS**: macOS / Linux のみ(`bash` + `python3` 必須)
- **Windows**: 生成時にビルダーが OS を自動判定し、hooks は最初から配置しません(README にその旨を記載。プロンプトベースの自己修復は残ります)
- **カスタマイズ**: `templates/hooks/*.sh` を編集すれば、生成プロジェクトの hook 挙動を変えられます
